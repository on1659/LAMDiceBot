# 모바일 경마 주문을 본문 화면으로

## 요청

2026-10-10: 사용자가 주문 목록을 팝업으로 띄우는 구조가 불필요하다고 지적했다. 실제 모바일 경마의 주문 기능을 앱 본문 화면으로 전환한다.

## 동작과 범위

- 하단 주문 도구를 누르면 게임 본문 대신 주문 입력과 전체 목록을 보여준다.
- 헤더와 하단 도구는 유지한다. 배경을 덮거나 주변 화면을 비활성화하지 않는다.
- 주문 도구를 다시 누르거나 게임으로 버튼을 누르면 게임 본문으로 돌아온다.
- 원본 주문 입력·목록 노드와 서버 이벤트를 그대로 사용한다. 작성 중 입력과 확정한 탈것 선택을 유지한다.
- 별도 주문리스트 팝업 버튼은 모바일 경마에서 숨긴다. 참여자·관전자 주문과 미주문자를 본문에서 바로 확인하고 정렬한다. 목록 내부의 200px 스크롤 제한을 없애 본문 전체가 스크롤된다.
- 주문 화면은 비모달 영역이다. 다른 메뉴·채팅의 기존 모달 동작은 유지한다.
- `js/mobile-game.js`, `css/mobile-game.css`, 독립 실제 주문 QA만 변경한다. PC 및 다른 게임, 서버·렌더러·공유 주문 모듈은 유지한다.
- 현재 검토 방 D8PKB는 QA에서 건드리지 않는다. 배포·push하지 않는다.

## 검증

- [x] 실제 주문 입력과 서버 반영이 두 클라이언트에서 동작한다.
- [x] 주문은 본문에 표시되며 헤더·하단 도구를 조작할 수 있다.
- [x] 이중 주문리스트 버튼/팝업 없이 전체 목록을 직접 확인하고 정렬한다.
- [x] 주문 재탭·게임으로·다른 도구 전환 후에도 입력/목록/탈것 선택과 원본 트랙을 유지한다.
- [x] 다른 모달의 접근성과 PC 원본 주문 위치 복원이 정상이다.
- [x] 320/375 라이트·다크 화면 및 관련 회귀 검사가 정상이다.
- [x] 구문·색 토큰·diff 검사 통과.

## 결과

- 실제 주문 QA 17 PASS, 브라우저 오류 0: `/tmp/mobile-horse-inline-orders-qa/final/report.json`.
- 서로 다른 두 클라이언트에서 원본 주문 저장을 실행해 서버 반영을 확인했다. 상대방의 주문 업데이트가 와도 작성 중인 미저장 내용과 입력 포커스가 유지된다.
- 모바일 주문은 normal flow의 region이며 헤더·하단 도구가 활성화된다. 이중 주문리스트 버튼과 별도 `orderListModal` 없이 원본 전체 목록·미주문자·정렬을 확인했다. 실제 경기 전 주문은 기존 서버 규칙에 따라 관전자 목록으로 표시했다.
- 주문 재탭/게임으로, 채팅·메뉴·참여자 이동, 키보드 이동, 선택 유지, 원본 트랙/주문 노드 유지, 320/375 라이트·다크, PC 원본 주문 위치와 팝업 복원을 검증했다.
- 최초 주문 진입에는 container와 window 스크롤을 함께 초기화한다. PC→모바일 전환 후 창 스크롤이 남아 헤더를 밀던 현상도 최종 재검증했다.
- 실제 주문이 채워진 증거: `/tmp/mobile-horse-inline-orders-qa/final/orders-filled-375-light.png`. root도 현재 검토 방에서 주문 도구를 열어 본문 화면과 하단 도구를 확인했다. 주문 저장/게임 시작은 하지 않았고 임시 viewport는 복원했다.
- 주사위·룰렛 smoke 각각 38 PASS/2 skip(실제 판 진행 생략), 오류 0: 같은 디렉터리의 `cross-dice/report.json`, `cross-roulette/report.json`. 게임 규칙·서버·렌더러 변경이 없어 경마 전체 경주를 반복하지 않았다.
- 구문·중앙 색 토큰·위험 DOM 패턴·diff 검사 통과. 변경은 모바일 어댑터/CSS와 독립 QA/명세뿐이다. 원래 checkout과 PC 기능은 유지하고 배포·push하지 않았다.
- 요구된 홈 밀도 측정 실행: `/mobile` 83자/12개, 홈 기준 미달. 변경하지 않은 로비를 이번 주문 개선으로 기준 통과했다고 주장하지 않는다.
- 실제 기기의 소프트 키보드 동작은 미검증이며 브라우저 viewport로 검증했다.
