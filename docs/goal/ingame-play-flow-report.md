# 인게임 사용 흐름 검증

2026-10-08. 작업 feature/home-proto / 배포 대상 feature/marble-run.

## 실제 게임 내부 변경
- 주사위: 내 차례/굴리기 완료/관전 안내, 실제 굴리기 비활성 상태, 참가자 진행표와 최종 점수표, 다음 판 준비. 기존 연출이 끝나기 전 결과를 노출하지 않는다.
- 룰렛: 참가 인원과 진행 안내, 게임판 시작/다음 판 준비 동작.
- 경마: 트랙의 실제 탈것을 클릭/Enter로 선택, 서버 선택 응답에 따른 이름/테두리 강조, 준비 전 비활성 안내.
- 데구리: 출발 위치 왼쪽/가운데/오른쪽 버튼은 기존 moveMyStart를 호출한다. 선택 동물·위치·따라가기 안내. 물리·렌더 결과 계산 변경 없음.

## 조작 배치
- 모바일 대기 화면의 시작 버튼 하단: 주사위170, 룰렛217, 경마435, 데구리405px (375×812 라이트).
- 진행·결과는 게임판 먼저. 모바일 하단에서 원본 준비/시작/굴리기/다음 판 조작에 접근한다.
- PC 활동 패널은 상단86~92px에서 게임 옆에 표시한다.
- 모바일 채팅/주문은 같은 DOM의 패널을 열고 닫아 기존 스크롤 위치를 유지한다. 기존 광고가 조작을 가리지 않도록 슬롯을 유지하고 본문에 배치했다.

## 검증
- 네 게임 실제2인 완주, JS 오류 없음. 주사위 단계별 버튼/진행/최종 기록 일치, 룰렛 게임판 시작과 다음 판 준비, 경마 트랙 클릭/Enter 선택과 전체화면 복귀, 데구리 위치 x216의 상대 클라이언트 수신 확인.
- 375/1280 × light/dark × 네 게임16화면 통과. 가로 넘침 없음, 대기 시작 버튼650px 이내, PC 채팅 위치160px 이내.
- 실제 하단 버튼으로 주사위 시작/양쪽 굴리기, 채팅 전달, 호스트 준비 드래그, 손님 새로고침/권한 복원 통과.
- 탭 키보드, 패널 Escape/포커스 복귀, 패널에서 상위 주문 모달로 포커스 이동, 튜토리얼 대상 탭/접힘 펼치기 검증.
- node --check 및 CRLF를 고려한 git diff --check 통과.
- 전체 색상 검사는 기존 home.css/deguri-render.js의30개 리터럴로 실패. 이번 변경 파일의 새 색 리터럴 없음.
- 로컬 전용 debugLogSection은 하단 버튼을 덮으므로 자동 브라우저 테스트에서만 숨겼다. 광고 네트워크도 테스트에서 차단한다. 네이티브 PiP 및 실제 휴대폰 키보드는 이번 headless 환경에서 직접 검증하지 않았다.

💡 lesson 후보: 게임 편의성은 스크롤 없음이나 기능 정상 여부와 별도로, 대기/진행/결과 각각에서 다음 조작이 손에 닿는지 검증해야 한다. 활동 패널의 포커스 trap은 상위 주문 모달과 Shadow DOM 튜토리얼에도 양보해야 한다.
