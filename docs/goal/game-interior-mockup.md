# 게임 내부 화면 디자인 검토와 경마 목업

2026-10-05. 사용자: 모바일 목업18의 다음 단계로 현재 통일된 게임 내부 UI를 바꿀 수 있는지 검토하고 디자인해 보기.

## 범위

- 공통 UI와 게임별 렌더 영역의 실제 의존성을 읽고 변경 가능한 경계를 설명한다.
- 운영 HTML/CSS/JS/소켓은 수정하지 않는다. 독립 `mockups/19.html`, `20.html`, `21.html`에서 경마 내부 화면 디자인을 비교한다.
- 사용자 추가 지시(2026-10-05): 15번과 16번을 기준으로 각각 만들고, 7번 모바일 느낌의 비교안도 추가한다. 19는 15의 청회색 작업대, 20은 16의 따뜻한 모임 보드, 21은 7의 숲색·라임 모바일 앱 구성을 이어 간다. PC는 게임 영역과 보조 도구를 나누고 모바일은 선택·준비·시작이 가까운 순서로 배치한다.
- 준비/탈것 선택/경주 장면/결과 등 화면 상태를 명시적으로 미리 볼 수 있게 한다. 고정 예시 데이터만 사용하고 게임 결과를 계산하거나 실제 서버를 조작하지 않는다.
- 초대·참여자·주문·채팅·기록·랭킹·설정·예약·꾸미기의 접근을 보존한다. 상세 실제 게임 링크/예시 한계를 명확히 한다.
- 실제 경마 선택 상태에서는 타인의 탈것 선택이 비공개라는 계약을 지킨다.
- 375×812 /1200×900, 라이트·다크와 화면 전환을 검증한다.

## 공통 UI 조사 결과

현재는 단일 게임 템플릿이 아니라 개별 HTML/CSS/렌더러와 공통 기능 모듈을 결합한 구조다. 공통 조작 규칙을 유지하면서 배치와 게임별 분위기를 바꿀 수 있다.

| 영역 | 근거와 구현 경계 |
|---|---|
| 상단 도구 | `js/shared/control-bar-shared.js:91` DOM 생성, `:117` 이벤트; `css/theme.css:1455` 스타일. 제목/방장/음량/퇴장 ID와 콜백 유지 |
| 준비/참가자 | 룰렛·경마·데구리는 `ready-shared.js`, 주사위는 자체 구현. 공통 파일 하나 변경만으로 전부 적용되지 않음 |
| 채팅 | `chat-shared.js:1406`은 chatMessages 부모의 첫 자식을 제목으로 간주. 제목/목록 구조를 바꾸면 후삽입 랭킹·고정메시지 처리도 조정 |
| 주문 | `order-shared.js`가 ordersSection/myOrderInput/orderSaveButton/orderList 등 ID와 방장/진행 콜백에 결합 |
| 랭킹 | `ranking-shared.js:652`가 오버레이와 CSS 생성. 시즌/필터/인증/뒤로가기 동작 보존 |
| 무대 | 경마 raceTrackWrapper/트랙과 데구리 캔버스는 개별 렌더. 주변 패널을 접거나 크기를 바꾸면 렌더러의 resize도 확인 |

- `deguri-multiplayer.html:40`이 `horse-race.css`를 함께 읽으므로 경마 공통 레이아웃 변경은 데구리에도 영향을 준다.
- JS가 상태마다 인라인 스타일과 후삽입 CSS를 적용하는 부분은 CSS 파일 수정만으로 끝나지 않는다.
- 실제 반영 순서: 공통 색/서체/여백 → 공통 도구 UI → 게임별 DOM 배치/모바일 패널 → 활성 게임의 준비/방장/소켓/재접속/resize 검증.
- 이번 작업은 독립 목업으로만 제공하며 위 운영 소스는 수정하지 않는다.


## 비교안 구성

| 시안 | 기준 | 화면 구성 |
|---|---|---|
| 19 작업대 게임룸 | 홈 15 | 청회색 작업대, PC 중앙 게임과 우측 채팅/주문, 모바일 하단 도구 |
| 20 보드 게임룸 | 홈 16 | 아이보리·점토색·올리브 정보판, 게임 보드 안의 참가자 줄, PC 비대칭 보드 |
| 21 손안의 게임룸 | 홈 7 | 숲색·라임과 둥근 카드, 최대 430px 앱 화면, 스크롤 영역 밖에 시작 버튼과 도구 |

- 세 안 모두 준비/선택/경주/결과 미리보기, 15종 탈것, 방장/참가자 전환과 라이트/다크를 제공한다.
- 채팅/주문 입력은 브라우저 메모리에서만 처리한다. 선택 전 다른 사람의 탈것은 숨기며 경주부터 공개한다.
- 초대/참여자/예약/꾸미기/경마 설정/방 설정/기록/랭킹/화면·소리 진입점이 있다. 랭킹과 꾸미기 등은 디자인 확인용 요약이며 실제 기능 전체를 재구현하지 않는다.
- 게임 결과와 기록은 고정된 예시다. API/Socket.IO 호출, 결과 계산, 실제 구매/전송/삭제는 없다.
- 목록 `/main`에서 세 모바일 화면을 나란히 비교하고 각 시안으로 이동할 수 있다.
