# 모바일 경마: 작은 미리보기에서 경주 전용 화면으로

## 요청

2026-10-10 사용자 승인: 대기 중에는 실제 경주 화면을 축소해서 보여주고, 게임 시작 시 확대하여 가로 화면으로 볼 수 있게 한다. 기존 실제 게임에 연결한다.

## 범위

- `js/mobile-game.js`, `css/mobile-game.css`의 경마 전용 모바일 화면.
- 기존 경주 DOM·스프라이트·서버 결과·전체화면 함수를 그대로 사용한다.
- 모바일 세로 대기 화면은 탈것 선택을 위에 두고, 선택 확인 후 접는다.
- 대기 트랙은 자연 좌표계를 유지하면서 시각적으로 축소한다.
- 카운트다운/시작 시 경주 전용 화면으로 진입하고 지원 환경에서는 가로 잠금을 시도한다. 불가능하면 기존 회전 안내와 세로 관전을 제공한다.
- 가로로 회전해도 모바일 UI를 유지하며 화면에 맞춰 경주를 확대한다.
- 실제 경주 애니메이션과 결과가 끝나면 자동 진입한 전체화면을 해제하고 결과·다음 판으로 돌아온다.
- 수동 전체화면 종료, 수동 전체화면 진입, PiP의 소유권을 존중한다.
- PC와 주사위·룰렛 화면을 유지한다. 서버·렌더러·테마 공통 파일 변경과 배포는 범위 밖이다.

## 검증 기준

- [x] 실제 트랙 노드를 유지하며 대기 축소/실제 경주/회전 후에도 스프라이트가 움직인다.
- [x] 실제 두 클라이언트의 선택·시작·서버 결과가 일치한다.
- [x] 세로 375×812 → 가로 812×375 → 세로 전환이 정상이다.
- [x] 결과와 다음 판에서 전체화면·회전 잠금·선택 상태를 정리한다.
- [x] 수동 종료 이후 같은 판에서 자동 재진입하지 않는다.
- [x] 전체화면/회전 API 미지원 환경에서도 경주를 볼 수 있다.
- [x] 320/375 라이트·다크 및 PC 1280×900을 확인한다.
- [x] 주사위·룰렛 공통 어댑터 회귀 검사, 구문·색 토큰·diff 검사를 통과한다.

## 결과

- 실제 원본 트랙을 자연폭 700px·높이 400px로 유지하고 부모만 축소한다. 전체화면에서도 같은 높이를 유지하여 레인 좌표가 달라지지 않는다.
- 기존 `raceFsEnter`/`raceFsExit`를 재사용한다. 자동 진입 소유권을 별도로 기록하여 사용자가 나가면 같은 판에서 재진입하지 않고, 수동 전체화면과 다시보기·PiP는 기존 기능에 맡긴다.
- 크게 보기/나가기 버튼 하나를 축소 영역 밖에서 재사용한다. 터치 높이는 44px이며 세로 전체화면에는 상단 공간 60px를 예약한다.
- `/tmp/mobile-horse-landscape-qa/final-fallback/report.json`: 실제 두 브라우저 경주 19 PASS, 오류 0. 브라우저 API 거부만 명시적으로 모의했고 게임 이벤트·움직임·결과는 실제 서버를 사용했다. 자연 높이 400px, 레인 전체 표시, 세로→가로→세로, 수동 종료 유지, 결과 자동 복귀, 다시보기, 다음 판 선택 초기화를 확인했다.
- `/tmp/mobile-horse-landscape-qa/native-api/report.json`: 실제 Fullscreen API 경로의 두 브라우저 경주 18 PASS, 오류 0. API 전체화면에서 Playwright 창 크기 변경 제한 때문에 CDP viewport metrics로 회전 상태를 검증했다. 이 경로의 PNG는 물리 창 크기와 달라 가로 화면 픽셀 증거로 사용하지 않는다.
- `/tmp/mobile-horse-landscape-qa/focus-regression/report.json`: UI 회귀 19 PASS. 실제 선택·채팅·주문·재접속 및 PC 원본 DOM 복귀를 검증했다. 기존 QA의 선택 선행 검증은 중첩 트랙에도 동작하도록 DOM 순서 비교로 변경했다.
- `/tmp/mobile-horse-landscape-qa/cross-dice/report.json`, `cross-roulette/report.json`: 각각 38 PASS, 실제 판 진행 2개 검사씩 명시적 skip. 이번 공통 어댑터 변경의 화면·도구 회귀 검사이다.
- 실제 가로 경주 증거: `/tmp/mobile-horse-landscape-qa/final-fallback/real-race-landscape.png` (812×375). root가 직접 확인한 375×812 대기 화면: `/tmp/mobile-horse-race-view-live.jpg`.
- `/tmp/mobile-horse-landscape-qa/final-portrait-controls/report.json`: 마지막 버튼 배치 보정 후 UI 전용 검사 8 PASS. 나가기 버튼 63.75×44px, 하단 52px ≤ 트랙 상단 60px로 겹침 없음. 수동 확대·세로/가로·미리보기 복귀와 모든 레인 표시를 확인했다. 이 실행은 실제 판 진행 검사를 반복하지 않았다.
- 로컬 검토용 새 방: `http://127.0.0.1:43113/free/horse/D8PKB`. 기존 QHND9는 새로고침 시 이미 종료된 상태라 로비로 돌아왔다. QA는 독립 방만 사용했다. 검토용 방에서는 탈것 선택과 경주 시작을 하지 않았다.
- 실제 iOS/Android 장치의 회전 잠금은 미검증이다. 기존 네이티브 코드가 잠금을 시도하고, 거부되면 회전 안내와 CSS 전체화면으로 관전을 유지한다. 자동 회전 성공을 보장하지 않는다.
- `node mockups/measure.js --url http://127.0.0.1:43113/mobile --ls freeUserName=라온`: 변경하지 않은 로비는 95자/12개로 홈 기준 미달. 이번 경마 화면 작업으로 홈 기준을 충족했다고 주장하지 않는다.
- JS 구문, 위험 DOM 패턴, 중앙 색 토큰, diff 공백 검사 통과. renderer·HTML·서버·테마 파일과 원래 checkout은 변경하지 않았으며 배포·push하지 않았다.
