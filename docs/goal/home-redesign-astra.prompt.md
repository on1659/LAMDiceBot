# LAMDice 홈 리뉴얼 — 다른 시각의 검토와 목업 (ASTRA 실행용)

> **쓰는 법:** 이 파일 전체를 ASTRA에 주고 "이 문서대로 실행해"라고 하면 된다.
> 저장소(`LAMDiceBot`, 브랜치 `feature/marble-run`)를 열 수 있으면 파일로 작업하고,
> 열 수 없으면 맨 아래 "저장소 없이 할 때"를 따른다.
> 작성: Claude, 2026-10-04. 같은 과제를 Claude가 먼저 했고(목업 1~10), 너는 **다른 눈으로** 다시 본다.

---

## 0. 너의 역할

너는 이 프로젝트를 처음 보는 제품 디자이너 겸 프런트엔드 개발자다.
Claude가 만든 목업 10종을 **비판적으로** 채점하고, Claude가 못 본 방향으로 목업을 새로 만든다.
동의만 하는 보고서는 쓸모없다. 틀렸다고 생각하면 근거와 함께 틀렸다고 써라.

## 1. 제품

- **LAMDice** (lamdice.com): 친구랑 링크 하나로 즉석에서 "오늘 누가 쏠지"를 정하는 무료 웹 내기 게임.
- 게임: 경마(탈것 15종, 가장 인기) · 주사위 · 룰렛 · 데구리(동물 구슬 굴리기, 베타). 사다리는 준비 중.
- 쓰는 사람: 한국 직장인·친구 모임. 대부분 **카톡 링크로 폰에서** 들어온다. 가입 없이 이름만 적고 논다.
- 결과는 서버 난수로만 정한다. 실제 돈은 오가지 않는다. 수익은 광고(AdSense).
- 기술: Express + Socket.IO, **프레임워크 없는 순수 HTML/CSS/JS**. 라이트·다크 스킨이 이미 운영 중.

## 2. 가장 중요한 기준 (사용자가 직접 한 말)

> "내가 생각하는 좋은 UI/UX는 **적게 읽고 직관성이 있어야 돼**.
> 꾸미는 건 있는 게 좋지만 그걸로 인해서 **스텝이 늘어난다던가 직관성이 떨어지면 안 돼**."

이걸 숫자로 옮긴 것(저장소 `DESIGN.md` 맨 위 "UX 원칙"):

| 항목 | 목표 | 재는 법 |
|---|---|---|
| 첫 화면 글자 수 | 60자 이하 | 폰 375×812, 공백 제외, 목업 전용 바 제외 |
| 첫 화면 조작 요소 | 6개 이하 | 버튼·입력·링크 개수 |
| 방까지 탭 수 | 다시 온 사람 1탭, 처음 온 사람 2탭(이름 한 번) | 직접 눌러 센다 |

꾸밈(그림·움직임·색·은유)은 **탭과 읽을 글을 늘리지 않는 곳에만** 허용된다.

## 3. 지금 실제 흐름 (실서버)

1. 첫 화면은 페이지가 아니라 전체 화면 오버레이다(`js/shared/server-select-shared.js`).
   "바로 플레이"(자유 방) 또는 로그인·회원가입(이름 + 4~6자리 숫자 암호코드).
2. 로그인하면 같은 화면이 **서버 목록**으로 바뀐다: 검색, 서버 카드(비공개 · 참여 가능 · 승인 대기),
   새 서버 만들기(이름·설명·참여코드), 내 서버 관리(멤버 승인·거절·강퇴).
   - **서버** = 팀 단위 상설 공간. 그 안에서 논 기록과 랭킹이 쌓인다. 자유 방은 기록이 안 남는다.
3. 서버를 고르면 그 서버의 로비(방 목록), 자유는 `/free` 로비(`dice-game-multiplayer.html`).
4. 로비에서 이름 입력 → "방 만들기" → 게임 선택 → 방(게임 화면).

새 방까지: **3탭 + 이름 타이핑**. 첫 화면과 로비의 디자인 언어가 서로 다르다는 게 리뉴얼의 출발점이었다.

### 10번이 한 선택 (네가 검증할 대상)

- 첫 화면 = 제목 한 줄("뭘로 정할까?") + 게임 그림 버튼 4개 + "열린 방 N ›" 한 줄 + 계정 버튼.
- 그림을 누르면 **바로 방이 열리고 링크가 복사**된다. 방 만들기 시트 없음.
- 이름: 다시 온 사람은 저장된 이름. 처음 온 사람은 그림을 누른 뒤 **제안 이름이 채워진 한 칸**만 뜬다.
- 방 이름·비공개는 방 안의 "방 설정"으로 옮겼다.
- 로그인한 사람: 지난번 서버가 자동으로 잡히고, 제목 위 "서버 이름 ▾"을 누르면 목록 한 장(가입 신청·코드·대기 중·자유 방·새 서버)이 뜬다. **서버 선택 화면이 따로 없다.**
- 뺀 것: 부제, 안내문, 통계, 노는 법, 팀 서버 홍보, "무엇을 걸까(커피/점심)" 칩.

## 5. 네가 할 일

### A. 채점 (필수)

1. 실서버와 목업 1~10을 직접 열어 보고(폰 폭과 PC 폭 둘 다) 2절 기준으로 다시 채점한다. 위 표의 Claude 평에 동의하지 않는 곳을 표시한다.
2. **10번의 약점을 최소 3가지** 찾는다. 예: 처음 온 사람이 "누르면 방이 생긴다"를 알 수 있는가, 실수로 누른 방은 어떻게 되는가, 서버 ▾ 한 장으로 승인 대기·참여코드·내 서버 관리를 다 감당할 수 있는가, 게임이 6개가 되면?
3. 기준 자체(60자·6개·1탭)가 이 제품에 맞는지도 의견을 낸다. 더 나은 측정 항목이 있으면 제안한다.

### B. 다른 시각의 목업 (필수 1개, 선택 1개)

- `mockups/11.html` (필수), `mockups/12.html` (선택).
- 10번과 **구조가 달라야** 한다. 색·서체만 바꾼 건 인정하지 않는다. 방향 예시(강제 아님):
  - 링크로 들어온 **초대받은 사람**의 첫 화면에서 출발하기 (지금까지는 전부 방 만드는 사람 기준이었다)
  - 게임을 고르지 않게 하기 (기본 게임으로 바로 열고, 방 안에서 바꾸기)
  - 방과 홈의 경계를 없애기 (들어오자마자 이미 내 방)
  - 폰 한 손 엄지 범위만 쓰기
- **반드시 포함:** 처음 온 사람 / 다시 온 사람 / 로그인한 사람 세 상태, 서버 고르기(가입됨·참여 가능·참여코드·승인 대기), 새 서버 만들기, 자유 방과 서버 방의 구분, 열린 방에 들어가기.
- 2절 수치를 `node mockups/measure.js 11 12` 로 통과시키고, 탭 수는 상태별로 직접 세어 적는다. 통과 못 하는 항목이 있으면 왜 그게 더 나은지 근거를 댄다.

## 6. 만들 때 지킬 것

**파일 형식**
- 목업은 **파일 하나짜리 HTML**. 프레임워크·빌드 도구·외부 JS 라이브러리 금지. CSS·JS는 파일 안에.
- `<head>`에 `charset`, `viewport`, `<meta name="robots" content="noindex, nofollow">`.
- 폰(375px)과 PC(1200px) 둘 다 깨지지 않게. 가로 스크롤 금지.
- 목업 전용 조작 바는 반드시 `id="mockBar"`로 만든다(측정에서 제외되는 기준). 한 줄로 작게. 허브 `/main`과 이전 번호 링크를 넣는다.
- 상태 전환(처음/단골/로그인 등)이 필요하면 그 바 안에 버튼으로 둔다.

**에셋** (`/mockups/assets/` 절대 경로로 참조)
- 아이콘 128px PNG: `ic-dice` `ic-slot`(룰렛) `ic-horse` `ic-paw`(데구리) `ic-ladder` `ic-trophy` `ic-people` `ic-person` `ic-link` `ic-lock` `ic-key` `ic-crown` `ic-medal` `ic-star` `ic-check` `ic-refresh` `ic-play` `ic-home` `ic-door` `ic-coin` `ic-fire` `ic-clock` `ic-chart` `ic-book` `ic-confetti` `ic-party` `ic-sparkle` `ic-gamepad` `ic-question` `ic-swords` `ic-d1`~`ic-d6`
- 탈것 달리기 2프레임 webp 120×90: `veh-{horse,rabbit,rocket,turtle,car,dinosaur,knight,ninja,crab,eagle}-{1,2}.webp` (0.34초 `steps(1)`로 번갈아)
- 데구리 동물: `mb-{hedgehog,hamster,panda,turtle,armadillo,pillbug}-idle.webp`(640×160, 4프레임 가로 스트립, 0.58초 `steps(4)`) / `-0.webp`(한 프레임 160×160)
- 픽셀 그림은 `image-rendering: pixelated`.
- 글꼴: 본문 Pretendard(jsdelivr `orioncactus/pretendard@v1.3.9` static dynamic-subset CSS), 제목은 Google Fonts에서 고른다(10번은 Bagel Fat One). `galmuri11-sub.woff`는 **서브셋**이라 숫자·영문에만 써라.
- 구현 예시는 `mockups/10.html`이 가장 짧다(약 300줄).

**내용**
- **이모지 금지.** 사이트는 픽셀 아이콘을 쓴다(7번이 이모지를 써서 어긋나 있다).
- 화면 문구는 평이한 한국어. fallback·default 같은 개발 용어를 노출하지 않는다.
- 노출 가능한 게임: 경마 · 주사위 · 룰렛 · 데구리(베타) · 사다리(준비 중 표시만). **다리건너기·해적룰렛·회전칼날은 어디에도 넣지 않는다.**
- 숫자·방 목록·서버 이름은 예시 데이터로 채운다. 빈 껍데기로 두지 않는다.
- 목업 안에서 게임 결과를 만들어 내지 않는다(결과는 서버가 정한다는 원칙). 무작위가 필요하면 고정값을 쓴다.
- 사용자가 입력한 값은 `textContent`로 넣는다. `innerHTML`에 넣지 않는다.

**저장소 규칙**
- 브랜치는 `feature/marble-run`. **`main`에 푸시하지 않는다**(`main` = 실서버 즉시 배포).
- 이 브랜치에 푸시하면 테스트 서버(`lamtest.up.railway.app`)에 1~2분 뒤 반영된다. `/11`은 라우트 수정 없이 열린다(`routes/api.js`가 `mockups/N.html`을 숫자 주소로 이미 연결. 테스트 서버·로컬에서만).
- 고쳐도 되는 파일: `mockups/11.html`, `mockups/12.html`, `mockups/index.html`, `docs/goal/home-redesign-astra-report.md`.
- **고치지 말 것:** `DESIGN.md`, `CLAUDE.md`, `routes/`, `socket/`, `js/`, `css/`, 기존 목업 1~10. 고치고 싶은 점은 보고서에 제안으로 쓴다.
- 같은 폴더를 다른 작업자가 동시에 쓰고 있다. `git add -A` 금지. **네가 만든 파일만** 골라 스테이징한다. 남의 미커밋 변경은 건드리지 않는다.
- 커밋 메시지는 한국어. 예: `feat(mockups): 11번 목업 추가 — (한 줄 요약)`.
