## 공통 규칙 — 플레이어별 화면에 맞추기

- **보는 사람 화면 상태만 만든다.** 수동 카메라·순위표 따라가기·동물 반응·마당은 소켓으로 보내지 않고, 다른 사람 화면에 영향이 없다. 새 소켓 이벤트는 없다. 예외는 20번의 방 상태 필드 추가(표시용)뿐이다.
- **자동 카메라는 지금처럼 결정적이다.** 공유 타임라인과 `t`, 그리고 그 사람의 '내 동물 따라가기' 설정만으로 정해진다.
- **카메라 우선순위:** 수동(손으로 옮김) = 순위표로 고른 동물 > LAMDice 기존 자동 카메라('내 동물 따라가기'가 켜져 있으면 그 규칙 → 시스템 카메라). 자동으로 돌아가면 이 기존 자동 카메라로 돌아간다.
- **강조 구분:** 순위표의 내 줄 강조(흰 글씨·강조 아이콘)와 "지금 카메라가 보는 동물" 표시(카메라 아이콘)는 모양이 달라야 한다.
- **동물 반응(12):** 내 화면에서만 보이고, 내 동물이든 남의 동물이든 다 반응한다.
- **공용 UI 부품은 건드리지 않는다.** ControlBar·채팅·주문·준비 목록·공용 `.result-overlay`/`.result-card`·다른 게임 CSS 는 그대로 두고, marble 전용 클래스·파일 안에서만 바꾼다. 여러 게임이 같이 쓰는 `js/shared/shop-shared.js` 는 옵션 훅 추가만 허용한다(15).

### 3단계 — 카메라 입력

**9. 수동 카메라**
- 렌더러 상태 `manual = { on, x, y, zoom, follow }`. 켤 때 지금 `cam` 을 복사해 화면이 튀지 않게 한다.
- 수동으로 바뀌는 입력:
  - 마우스 왼쪽 드래그·한 손가락 드래그(6px 문턱)
  - 두 손가락 핀치(가운데 기준 확대 + 이동)
  - ctrl+휠(트랙패드 핀치, 커서 기준 확대)
  - **일반 휠은 페이지 스크롤이다.** 옛 문서의 "휠 = 이동"은 데구리 `6628dd3` 에서 되돌렸다.
- `updateCamera`: `manual.on` 이면 목표는 manual 값이되, 자동 카메라와 같은 세로·가로 한계 안에서 정한다. 한계에 걸린 값을 manual 에 되써서, 끝까지 끈 뒤 반대로 끌 때 헛도는 구간이 없게 한다. 스무딩 없이 바로 적용한다. 줌 범위는 데스크톱 `ZOOM_MIN`~`ZOOM_MAX`, 폰 0.8~`ZOOM_MAX`.
- 자동으로 돌아가는 때:
  - 카메라 버튼(10)이나 더블클릭
  - 꼴찌가 정해질 때(비석·축하 장면을 놓치지 않게)
  - `setTimeline`(새 경주·다시 보기)과 `drawIdle`
- 터치:
  - 경주가 **진행 중일 때만** `canvas.style.touchAction = 'none'` 으로, 터치 드래그가 페이지 대신 카메라를 움직이게 한다.

- API(추가만): `isManualCamera()`, `setManualCamera(on)`, `onCameraModeChange(cb)`, `debug().cam.mode`.
- 입력 핸들러는 렌더러 안에 둔다. `js/marble.js` 에 캔버스 포인터·휠 핸들러가 없는지 확인하고, 있으면 합친다.

### 4단계 — HUD

**19. HUD 정리**
- 당첨 규칙 배지(~1847-1851)를 순위표 바로 위로 옮기고, 순위표와 폭·정렬을 맞춘다. 배지는 아틀라스 `target` 아이콘 폭을 포함해 계산한다.
- 순위표 내용은 가운데 정렬한다.
- 왼쪽 위 상태 문구(~1841-1845)는 **전체화면이 아닐 때** 2배속 구간에만 보인다. **전체화면에서는 지금처럼 계속 보인다.** 캔버스 밖 HTML 상태가 안 보여서 유일한 진행 정보이기 때문이다.
- 순위표 시작 높이는 `HUD_RANK_TOP_PX = 56` 을 유지한다. 배지만큼 내려가니 폰에서 5번 상한(42%) 안에 배지 높이도 포함해 계산한다.

## 공정성

- 결과는 지금처럼 서버에서만 결정한다. 이 goal 은 시뮬레이션·RNG·타임라인·당첨 판정을 바꾸지 않는다.
- 클라 `Math.random` 은 결과 계산에 쓰지 않는다. 12·23의 반응·마당 연출은 화면 장식이라 예외지만, 결과·타임라인·다른 사람 화면에 닿지 않는다.
- reveal 전 서버 전용 정보는 노출하지 않고, 재진입 마스킹도 유지한다. 20번의 방 상태 추가 필드는 설정값에서 계산한 표시용이다.

## 기존 통합 유지 (스킵 금지)

- 통계·랭킹·튜토리얼·사운드·주문·채팅·예약 시작·다시 보기·재접속 복원·가챠·상점이 계속 동작해야 한다.
- `marble:reveal`·`marble:gameEnd` 페이로드는 바꾸지 않는다. 렌더러 API 는 추가만 한다.
- '내 동물 따라가기' 스위치(강조+카메라, 탭 단위 저장)의 동작은 그대로다.
- 전체화면 버튼(iOS 숨김 포함)과 전체화면 크기 처리는 그대로다.
- 다른 게임 페이지(경마 등)는 영향이 없어야 한다. 공용 파일은 훅 추가만 한다.

## 작업 방식

- 단계 순서: 1단계 버그(1~8) → 2단계 렌더 다듬기 → 3단계 카메라 입력(9·10·11·12·21) → 4단계 HUD(19) → 5단계 결과창(22) → 6단계 대기실·상점(15·20·23·24).
- 한 단계를 끝내고 검증한 뒤 다음 단계로 간다. 커밋은 저장소 규칙대로 단계 단위로 나눠, 되돌리기 쉽게 한다.
- 각 항목은 데구리 커밋 diff 를 먼저 읽고 LAMDice 해당 함수와 비교한 뒤 옮긴다. 통째로 복사하지 않는다(위 "가져오지 않는다" 목록).
- 계획 단계부터 폰(375×812, 390×844)과 데스크톱(≥600px), 전체화면(Android Chrome·데스크톱)을 같이 본다.

  - 6단계: 다크 모드 대비, 경마 페이지·상점 공용 UI 무변화
- 콘솔 오류 0, 새 에셋(`camera-auto.png`, `camera-manual.png`) 200 응답

## 막힘 기준

- 세부 수치·배치(카메라 버튼 위치, 줄 높이, 말풍선 모양, 마당 띠 높이, 다크 모드 색)가 애매하면 기존 LAMDice 구조를 조사한 뒤 근거를 적고 합리적으로 고른다.
- 20번의 서버 값 전달이 방 상태 구조상 무거우면 클라 계산으로 해도 된다. 대신 서버와 같은 함수를 공유하는 방법(공용 모듈)을 먼저 찾아보고, 결정과 이유를 보고한다.
- 한 항목이 LAMDice 구조 때문에 원래 의도대로 안 되면 그 항목만 멈추고 이유를 보고한다. 나머지 단계는 계속한다.
- 폰 실기 테스트가 불가능하면 에뮬레이션(375×812, 터치)으로 하고, 무엇을 못 봤는지 구체적으로 적는다.
