# 모바일 경마 앱 화면 재구성

## 승인과 목적

2026-10-11 사용자가 "지금 레이아웃 다 바꿔도되니까 다시만든다생각하고 해"라고 승인했다. 실제 모바일 경마 화면을 새로 구성한다. 앞선 변경에서 누락한 주문 정리표를 복구하고, 게임·주문·채팅을 앱 본문에서 직접 오가게 한다. 현재 PC 화면은 유지한다.

## 구조

- 공통 방 헤더와 게임/주문/채팅/메뉴 하단 탐색. 기본 화면은 본문 전환이며 닫아야 하는 팝업을 늘리지 않는다.
- 게임 대기: 탈것 선택이 먼저, 서버 확인 후 접힘, 명시적 변경, 작은 원본 경주 미리보기, 준비/시작 행동 하나.
- 경주: 기존 실제 트랙·스프라이트·서버 결과와 전체화면/가로 대응을 유지한다. 결과·다음 판·수동 종료·다시보기·PiP 소유권을 보존한다.
- 주문: 간결한 내 주문 입력과 메뉴/수량/주문자 정리표를 같은 본문에서 바로 본다. 메뉴 종류·주문 인원 합계와 미주문자를 표시한다. 참여자/관전자 구분을 유지한다.
- 수량은 기존 주문 묶음의 주문자 수이며 주문 문장을 임의로 분석하지 않는다. 실제 주문 데이터에서만 집계하고 상대방의 주문 업데이트에도 미저장 입력과 포커스를 보존한다.
- 정렬·자주 쓰는 메뉴·디폴트 주문, 방장 주문 시작/종료, 참여자·랭킹·기록·규칙·설정·초대·꾸미기를 유지한다.
- 기존 모바일 토큰으로 화면들의 색·서체·간격을 통일하고 중복 제목과 큰 카드 장식을 줄인다. 긴 이름과 메뉴도 읽고 조작할 수 있다.

## 구현 경계

`js/mobile-game.js`, `css/mobile-game.css`의 모바일 경마 분기, 필요한 모바일 전용 파일, 독립 QA 및 이 명세. 원본 DOM·이벤트를 재사용하고 PC 복귀 시 위치와 접근성 속성을 복원한다. 서버/DB/결과 계산과 다른 게임의 UI는 변경하지 않는다. 작업 위치는 `codex/mobile-live-ui` worktree이며 배포·push는 포함하지 않는다. 기존 사용자 방 D8PKB는 테스트에서 조작하지 않는다.

## 확인한 기존 계약

같은 탈것 재선택은 서버의 선택 취소다. 현재 `horseSelectionUpdated` 개인 map은 취소 때도 클릭한 index를 담지만 `selectedUsers`에는 취소가 반영된다. 모바일 대기 화면은 선택자 목록도 함께 확인하고, 랜덤 확정은 `mySelectedHorse === -999`를 우선해 표시한다. 서버·원본 게임 계약은 이번 작업에서 수정하지 않는다.

원본 경마 메뉴관리 영역은 `active` 클래스를 토글하지만 인라인 `display:none`과 class 누락으로 열리지 않는다. 추가 입력 ID도 HTML의 `newMenuInput`과 모듈의 `menuInput`이 다르다. 모바일 CSS와 adapter 활성 중 ID 정합으로만 보완하며 PC 복귀 시 원래 ID를 복원한다.
