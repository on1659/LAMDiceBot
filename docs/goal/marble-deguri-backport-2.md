## 공통 규칙 — 1차와 같음

- **보는 사람 화면 상태만 만든다.** 마당 연출·사용자 배율·미니맵 이동은 소켓으로 보내지 않고, 다른 사람 화면에 영향이 없다. 새 소켓 이벤트·방 상태 필드는 없다. 결과·시뮬레이션·타임라인은 그대로다.
- **자동 카메라는 지금처럼 결정적이다.** 공유 타임라인과 `t`, 그 사람의 '내 동물 따라가기' 설정으로 위치·따라가기·결승 프레임을 정한다. 알약(3)은 그 결과 배율에 그 사람의 사용자 배율을 곱할 뿐 판단은 바꾸지 않는다.
- **카메라 우선순위는 1차 그대로다:** 수동(손으로 옮김) = 순위표로 고른 동물 > 기존 자동 카메라. 미니맵(4)은 "손으로 옮김"에 새 입력 하나를 더한 것이다.
- **공용 UI 부품·공용 CSS 는 건드리지 않는다.** `js/marble-render.js`, `js/marble.js`, `css/marble.css`(2번은 `css/marble-gacha.css` 포함) 안에서 marble 전용 클래스로만 바꾼다. 렌더러 API 는 추가만 한다.
- **데구리 현지화는 가져오지 않는다.** 위 "데구리 코드 읽는 법"의 목록을 따른다.

### 1. 동작 줄이기가 켜진 폰에서도 마당이 차분히 움직인다

**무엇**
- 지금은 `prefers-reduced-motion: reduce`(iOS '동작 줄이기', 안드로이드 '애니메이션 제거')면 마당을 통째로 숨긴다. 이것을 **차분한 모드**(`calmMode`)로 바꾼다. 숨기거나 세워 두지 않고, 차분한 동작만 천천히 한다.
- 이유(데구리 결정, 사용자 2026-09-24): 폰에서 이 설정을 켠 사람이 많다(사용자 폰도 켜져 있었다). 숨기면 마당이 통째로 안 보이고, 세워 두면 멈춘 그림 같았다.
- 데구리 차분한 모드:
  - 동작 가중치에서 `roll`·`jump` 를 뺀다. 걷기·서 있기·손 흔들기·낮잠·떠나기(`walk`·`idle`·`wave`·`nap`·`leave`)만 남는다.
  - 걷기 속도는 24~40(평소 38~70)이고, 걷다 넘어지기(`tripAt`)가 없다.
  - `meet()` 을 건너뛴다. 구르는 공에 부딪혀 놀라기, 마주쳐 몸싸움·폴짝이 없다.
  - 누르면(`poke`) 손 흔들기·낮잠 중 하나만 한다(평소는 놀람·낮잠·점프·손 흔들기·넘어짐·구르기).
  - 설정은 시작할 때 한 번 읽는다. 바꾸면 새로고침 뒤 반영된다.

**데구리 참조:** `86a853c`(최종), `a3bac86`(숨김 → 세워 두기. 중간 단계라 세워 두기는 가져오지 않는다). `js/main.js` `startIntroCritters` 의 `calmMode`·`WEIGHTS`·`start`·`meet`·`poke`.

**LAMDice 맞춤**

### 2. 마당 그림 칸 `inset: 0` → 네 변 지정 (iOS 14.4 이하 사파리)

**무엇**
- `inset` 속성은 사파리 14.1(iOS 14.5)부터 된다. iOS 14.4 이하에서는 `inset: 0` 이 무시된다. 그래서 크기를 `inset` 에만 기대던 절대 위치 칸이 크기 0이 되고, 마당 동물이 안 보인다.
- `.marble-yard-critter__body { inset: 0; }` 를 `top: 0; right: 0; bottom: 0; left: 0;` 으로 바꾼다.

**데구리 참조:** `a3bac86`, `css/standalone.css` `.intro-critter__body`.

**LAMDice 위치:** `css/marble.css` `.marble-yard-critter__body`(~921-927, `inset: 0` ~923).

**LAMDice 맞춤 — 다른 `inset` 도 바꿀지 판단 기준.** 세 가지가 다 맞으면 바꾼다.
1. 데구리 전용 파일·구역이다: `css/marble.css`, `css/marble-gacha.css`, `marble-multiplayer.html` 의 인라인 스타일, `js/marble*.js` 가 넣는 인라인 스타일. 공용 CSS(`theme.css`, `ui-icons.css`, `horse-race.css`, `horse-shop.css` 등)는 marble 페이지가 불러와도 건드리지 않는다.
2. 위치를 정하는 `inset` 속성이다. `box-shadow: inset …`, `env(safe-area-inset-*)`, `clip-path: inset(…)` 은 대상이 아니다.
3. `position: absolute | fixed` 이고 크기를 `inset` 으로 정한다. 너비·높이를 따로 주지 않았다.

### 3. 확대·축소 알약 `− 100% +` (데스크톱만)

**무엇**
- 카메라 버튼 바로 위에 알약 하나를 둔다: `−` · 가운데 배율 % · `+`. 한 번 누를 때 배율을 ×1.25(`ZOOM_STEP`) 또는 ÷1.25 한다.
- **자동 카메라:** 위치·따라가기·결승 프레임 판단은 그대로 두고, 자동 카메라가 고른 배율(`cam.autoZoom`)에 사용자 배율(`userZoom`)만 곱한다. 그래서 동물이 화면 밖으로 나가지 않는다.
  - 곱한 배율이 1보다 크면(경주 중, `t ≥ 0`) 따라가는 동물을 가로로도 가운데에 둔다.
  - 결승 프레임에서 곱한 배율이 맞춤 배율(`fitZoom`)보다 커서 프레임이 다 안 들어가면, 초점 동물(선두 / 꼴등 규칙 마지막 1/3 은 후미)을 프레임 안에서 따라간다. 더 줌아웃이면 프레임 가운데 그대로다.
  - 배율 한계(`manualZoomMin()`~`ZOOM_MAX`)에 닿아 배율이 안 바뀌면 `userZoom` 도 그대로 둔다. 그래야 반대 버튼이 바로 먹는다.
- **수동·따라가기 중:** 핀치처럼 화면 가운데를 기준으로 그 카메라 배율(`zoomBy`)을 바꾼다.
- **가운데 %:** 자동이면 `userZoom`(100% = 자동 카메라 기본)이다. 수동이면 수동으로 바뀐 순간의 자동 배율(`manual.base`) 대비 `manual.zoom` 이다. 핀치·ctrl+휠·순위표 따라가기로 배율이 바뀌어도 바로 반영된다. 숫자를 누르면 100%로 돌아간다(자동은 `userZoom = 1`, 수동은 화면 가운데 기준 `zoomBy(base / zoom)`).
- **초기화:** 자동으로 돌아올 때(`setManual(false)` — 카메라 버튼·더블클릭·꼴찌 확정·새 타임라인·대기 화면)와 경주·다시 보기 시작(`R.play`)에 `userZoom = 1` 로 한다.
- **데스크톱에만 보인다.** 폰은 핀치로 충분하고 알약이 화면만 가린다(사용자 2026-09-24). 폰↔데스크톱으로 크기가 바뀌면 `R.resize` 가 표시를 따라가게 한다.

**데구리 참조:** `7d929c5`(+ − 버튼, 자동은 배율만 곱하기), `9ae84db`(`− 100% +` 알약, `manual.base`, 숫자 = 100%), `ed54523`(폰 숨김 + `resize` 갱신). `js/marble-render.js` 의 `userZoom`·`zoomStep`·`zoomReset`·`zoomRatio`·`updateZoomLabel`, `updateCamera` 의 `cam.autoZoom` 두 곳, `css/standalone.css` `.camera-zoom*`. 기록: `docs/lamdice-deguri-localization.md` "2026-09-24 카메라 확대·축소 버튼".

**LAMDice 위치** (`js/marble-render.js`)
- 상수(~64-87): `ZOOM_STEP = 1.25` 를 추가한다.
- 상태(~269): `manual` 에 `base`, 새 변수 `userZoom`.
- `R.debug`(~287): `userZoom` 을 추가한다(테스트용, 추가만).

- `updateCamButton`(~373-384): 알약 `hidden` 과 % 를 갱신한다. 알약은 카메라 버튼 만드는 곳(~385-400)에서 같이 만들어 같은 부모(`#marbleCanvasBox`)에 붙인다.
- `zoomBy`(~414): 끝에서 % 를 갱신한다. `followBall`(~423)은 이미 `updateCamButton` 을 부른다.
- `updateCamera`(~601-708): 결승 프레임 분기(~646-664) 안, 그리고 그 밖의 자동 분기 전부(폰 줌 하한 ~681-684 뒤)에서 `cam.autoZoom` 을 기록하고 `userZoom` 을 곱한다.
- 순위표 높이: `drawHud` 의 `panelMaxH`(~2202), `HUD_RANK_BOTTOM_GAP`(~80).
- `css/marble.css`: `.marble-cam-btn` 블록(~478-517) 뒤에 알약 스타일을 두고, reduced motion 블록(~667-675)에서 전환을 끈다.

**LAMDice 맞춤**
- **보이는 때:** 카메라 버튼과 같은 조건(`data` 가 있고 `phase !== 'idle'`)이면서 폰이 아닐 때. 폰 판정은 `view.narrow` **또는** `matchMedia('(hover: none) and (pointer: coarse)')` 로 한다. 가로로 눕힌 폰(특히 전체화면)은 폭이 600 이상이라 `view.narrow` 가 아니다. 폭 기준만 쓰면 사용자가 뺀 폰에서 알약이 다시 보인다.
- **숨을 때 100%로:** 알약이 숨는 쪽으로 바뀌면(창이 폰 폭으로 줄어듦) `userZoom = 1` 로 한다. 안 보이는 배율이 남지 않게 하는 것으로, 데구리엔 없는 보완이다.
- **자리:** 카메라 버튼(`.marble-cam-btn`, `right: 10px; bottom: 10px`, 높이 ≈38)이 아래 오른쪽에 있으니 알약도 오른쪽 정렬로 그 바로 위(`right: 10px; bottom: ≈54px`)에 둔다. 캔버스 박스 안이라 전체화면에서도 보인다.
  - 다시 보기 배지(아래 가운데 `bottom: 10px`), 다시 보기 채팅(아래 왼쪽 260px), 베타 배지·전체화면 버튼(위 오른쪽)과 겹치지 않는다. 예약 시작 배지는 대기 화면에서만 떠서 알약(대기 화면에선 숨김)과 만나지 않는다.
  - **순위표(캔버스 HUD, 오른쪽 위)와 겹침:** 지금 순위표 아래 여백 `HUD_RANK_BOTTOM_GAP = 60`(HUD 단위)은 카메라 버튼(≈46 CSS px)만 계산한 값이다. 알약이 보일 때는 이 여백을 카메라 버튼 + 알약(≈100 CSS px)을 HUD 단위로 바꾼 값 이상으로 늘린다. 환산은 `hudTop` 과 같은 `px * hw / view.cssW` 다. 안 늘리면 데스크톱 20마리+ 경주에서 순위표 아래쪽 줄이 알약 밑에 깔리고, 알약이 그 줄 클릭을 가로챈다.
- **'내 동물 따라가기'(`highlightMine`) 자동 카메라에서도 배율만 곱하는 방식은 성립한다.** `mine` 분기(~642)는 위치(내 동물 y + `CAM_LEAD`, x 가운데)만 정하고 배율은 1 이라서 곱하기만 하면 된다. 다만 세 가지를 맞춘다.
  - 가로로 따라갈 동물: 데구리의 `fz = carried || focus` 를 LAMDice 에선 `carried || myFocus || focus` 로 한다. 안 그러면 확대했을 때 가장자리에 있는 내 동물이 화면 밖으로 나간다.
  - 세로 앞당김: 선두·후미·`mine` 분기는 배율 1 일 때 `view.h * CAM_LEAD` 를 배율로 나누지 않고 쓴다. 여기에 사용자 배율 1.7 을 곱하면, 보이는 반높이(≈0.29 view.h) 안에서 0.22 만큼 위라 따라가는 동물이 화면 위 1/8 지점에 붙는다. 사용자 배율로 1 넘게 확대될 때는 선두 분기의 확대 구간(~669)처럼 `view.h * CAM_LEAD / targetZoom` 으로 다시 잡는다. 데구리는 가로만 옮긴다.
  - 결승 프레임인지는 `frameMode` 변수가 아니라 **프레임 분기를 실제로 탔는지**로 가른다. LAMDice 는 선두가 프레임 구역에 들어와도 내 동물이 아직 위에 있으면 `mine` 분기를 탄다. 이때 `frameMode` 는 true 다. 데구리식 `!frameMode` 조건을 그대로 옮기면 이 구간에서 사용자 배율이 빠진다. 프레임 분기 안에서 지역 표시를 세워 판단한다.
  - 내 동물이 프레임 구역에 들어와 `mine` 이 풀리면 프레임 분기가 `fitZoom × userZoom` 으로 이어받는다. 배율은 끊기지 않는다(줌 스무딩 그대로). 카메라 버튼 문구 '내 동물 따라가는 중'(~706-707)도 그대로다.
- 독수리 운반(`eagle`)·1등 축하(`celebrate`)·비석 장면도 같은 곱하기로 된다. 축하 장면의 가로 클램프 건너뛰기는 유지한다. 꼴찌 확정 때 이미 자동이면 `setManual(false)` 가 일찍 끝나서 `userZoom` 이 유지된다(데구리와 같다).
- **스타일:** 카메라 버튼과 같은 어두운 알약이다. 배경 `rgba(43, 36, 22, 0.88)`, 테두리 `--marble-gold-deep`, `−`·`+` 글자 `--marble-gold`, focus-visible 외곽선 `--marble-gold`.
  - 가운데 % 글자에는 `--marble-cream` 을 쓰지 않는다. 다크 테마(`[data-theme="dark"]`, css/marble.css ~97-108)에서 `#33291b` 로 바뀌어 어두운 알약 위에서 안 보인다. 카메라 버튼 `.is-manual`(~504-508)처럼 `#fff8e6` 을 고정으로 쓴다.
  - `display: inline-flex` 를 주면 `[hidden] { display: none; }` 규칙도 같이 둔다.
  - 클래스는 marble 접두로 한다(`.marble-zoom-pill`, `__btn`, `__value`).
- 글자는 `−`(U+2212)·`+`·`%` 를 쓴다. 공용 아이콘 아틀라스에 확대·축소 칸이 없고, OS 이모지도 아니다. 새 리소스는 없다.
- 버튼마다 `aria-label`(`카메라 축소` / `카메라 배율 100%로 되돌리기` / `카메라 확대`)과 `title` 을 단다.

### 4. 미니맵을 누르거나 끌면 카메라가 그 지점으로

**무엇**
- 미니맵의 한 점을 누르면 수동 카메라로 바뀌고, 순위표 따라가기는 풀린다. 그 트랙 지점이 화면 가운데로 온다. 배율은 그대로다.
- 놓을 때까지 끌면 손가락·커서를 따라 계속 옮긴다. 끄는 동안 미니맵 밖으로 조금 벗어나도 가장자리로 조여서 이어진다. 손가락용 여유는 6(HUD 단위)이다.
- 미니맵은 일반 드래그·핀치와 섞이지 않게 **별도 포인터**로 다룬다(`pointers` 에 넣지 않는다).
- 마우스를 미니맵 위에 올리면 포인터 커서가 된다.

**데구리 참조:** `0fee29e`. `js/marble-render.js` 의 `mmRect`·`mmHitAt(p, force)`·`jumpTo`·`mmDrag`, `drawMinimap` 의 `mmRect` 기록, `drawHud` 의 `mmRect = null`. 기록: `docs/lamdice-deguri-localization.md` "2026-09-24 미니맵으로 카메라 이동".

**LAMDice 위치** (`js/marble-render.js`)
- 미니맵: 상수 `MINIMAP_*`(~68-73). `mmCache`(~2059) 옆에 `mmRect` 를 둔다. `drawMinimap`(~2094-2124)에서 `sc`·`w`·`h` 를 구한 직후 `mmRect = { x0, y0, w, h, sc, startY }` 를 채운다. `drawHud`(~2152)의 `rankHits = []`(~2187) 자리에서 `mmRect = null` 로 비운다. `drawMinimap` 은 `phase !== 'idle'` 일 때만 불린다(~2226, 1차 25번).
- 판정·이동: `rankHitAt`(~428-432) 옆에 `mmHitAt`·`jumpTo` 를 둔다. 좌표 환산은 `rankHitAt` 과 같은 `logicalPerCss() / view.ui` 다. 미니맵도 `drawHud` 의 `view.ui` 배율 안에서 그리기 때문이다.
- 입력: `bindCameraInput`(~437-500)의 `pointerdown`(~444), `pointermove`(~461, 커서 ~462), `release`(~482), `dblclick`(~499).

**LAMDice 맞춤**
- **검사 순서:** `pointerdown` 에서 `!data` 가드(~445) 바로 뒤, 동물 반응 판정(~446-449)보다 **먼저** 미니맵을 본다. 조건은 `!ids().length && mmDrag == null && racing()` 이다. 미니맵은 월드 위에 그린 HUD 라서, 결승 스탠드 동물이 미니맵 밑에 있어도 누른 사람은 미니맵을 누른 것이다. 데구리 코드는 커밋 본문("동물·순위표 클릭보다 먼저")과 달리 동물 판정을 먼저 한다. LAMDice 는 본문 의도대로 한다. 순위표(~451)와는 왼쪽·오른쪽으로 떨어져 있어 겹치지 않는다.
- **동물 반응과의 관계:** LAMDice 동물 반응은 누를 때가 아니라, 뗄 때 탭이었으면 반응한다(`dragFrom.critter`, ~448·~485). 미니맵 포인터는 `pointers`·`dragFrom` 을 건드리지 않으니 이 흐름과 섞이지 않는다.
- **미니맵을 끄는 동안 다른 포인터는 받지 않는다.** 데구리는 두 번째 손가락이 일반 드래그로 들어가서 `jumpTo` 와 `panBy` 가 `manual.x/y` 를 번갈아 덮는다. LAMDice 는 `mmDrag != null` 이면 `pointerdown` 에서 바로 돌아간다.
- **`release`:** `mmDrag === e.pointerId` 면 `mmDrag = null` 하고 바로 돌아간다. 그래야 아래 줄의 "핀치에서 한 손가락이 남으면 끌기로"(~488)에 걸리지 않는다. `pointercancel` 도 같은 함수를 쓴다.
- **더블클릭:** 미니맵 위 더블클릭은 자동 복귀(~499)로 치지 않는다. 미니맵을 연달아 두 번 눌러 옮기는 사용자가 두 번째에 자동으로 튕기지 않게 한다.
- **대기 화면 규칙(1차 9번)과의 관계:** 대기 화면에는 미니맵이 없다(1차 25번). 그래서 `mmRect` 가 null 이고 미니맵 입력도 없다. `racing()` 조건도 같이 걸어 둔다. 대기 화면 페이지 스크롤은 그대로다.
- **경주가 끝난 뒤(`phase done`, ~2266):** 폰에서는 `touch-action` 이 풀려 있다(1차 9번, 결과·주문 쪽으로 스크롤하게). 미니맵 탭 이동은 되지만, 끌기는 브라우저가 페이지 스크롤로 가져가 `pointercancel` 로 끝날 수 있다. 1차의 "경주 뒤 페이지 스크롤 보장"이 우선이니 그대로 둔다. 마우스 끌기는 된다.
- 꼴찌 확정 때 자동으로 돌아간 뒤(~672-673)에도 미니맵을 누르면 다시 수동이 된다. 순위표 따라가기와 같은 규칙이다. 수동 카메라에는 스무딩이 없어서 미니맵의 흰 화면 범위 네모가 바로 따라온다.

## 공정성

- 결과는 지금처럼 서버에서만 결정한다. 이 goal 은 시뮬레이션·RNG·타임라인·당첨 판정을 바꾸지 않는다.
- 클라 `Math.random` 은 쓰지 않는다. 마당은 기존 시드 PRNG(`rand01`)를 그대로 쓰고, 화면 장식이라 결과·타임라인·다른 사람 화면에 닿지 않는다.
- reveal 전 서버 전용 정보는 노출하지 않고, 재진입 마스킹도 그대로다. 카메라 입력(3·4)은 이미 받은 공유 타임라인을 어디서 보느냐만 바꾼다.

## 기존 통합 유지 (스킵 금지)

- 1차 25개가 그대로 동작한다: 수동 카메라(드래그·핀치·ctrl+휠, 일반 휠은 페이지 스크롤), 카메라 버튼, 순위표 따라가기·카메라 표시, 동물 반응, 결과 카드, HUD, 마당(평소 모드의 구르기·몸싸움·장애물 포함).
- 통계·랭킹·튜토리얼·사운드·주문·채팅·예약 시작·다시 보기·재접속 복원·가챠·상점이 계속 동작한다.

- 경마 등 다른 게임 페이지는 영향이 없다. 공용 파일은 바꾸지 않는다.

## 작업 방식

- 순서: 1단계 마당(2 → 1) → 2단계 알약(3) → 3단계 미니맵(4). 3·4는 같은 `bindCameraInput`·`updateCamera` 를 만지니 한 단계씩 끝내고 검증한다. 커밋은 저장소 규칙대로 단계 단위로 나눈다.
- 각 항목은 데구리 커밋 diff 를 먼저 읽고 LAMDice 해당 함수와 비교한 뒤 옮긴다. 통째로 복사하지 않는다("가져오지 않는다" 목록 참고).
- 계획 단계부터 폰(375×812, 390×844, 가로 844×390)과 데스크톱(≥600px), 전체화면(데스크톱·Android Chrome)을 같이 본다.

  - 데스크톱 1280×800 경주 중: 알약이 카메라 버튼 바로 위에 있고, 요소 사각형이 카메라 버튼·다시 보기 배지·베타 배지·전체화면 버튼과 겹치지 않는다. 데스크톱 20마리+ 경주 스크린샷에서 순위표 마지막 줄이 알약 위에서 끝난다.

  - 수동: 드래그로 수동이 된 직후 % 는 그 순간 화면 배율 ÷ 자동 배율이다(스무딩 중이면 100% 가 아닐 수 있다). `+` 한 번에 % 가 1.25배가 된다. ctrl+휠·순위표 따라가기에서도 % 가 바로 바뀌고, 숫자 → 100%.
  - 초기화: 카메라 버튼·더블클릭·꼴찌 확정·다음 경주·다시 보기로 100%가 된다.
  - '내 동물 따라가기'를 켜고 `+` 두 번: `cam.mode` 가 `mine` 인 동안 내 동물이 가로·세로 모두 화면 안쪽에 있다(위 1/8 에 붙지 않음). 선두가 프레임 구역에 먼저 들어간 구간에서도 배율이 유지된다.
  - 데스크톱 전체화면에서 보이고 눌린다.
  - 폰 375×812·390×844·가로 844×390(터치): 알약이 `hidden` 이다. 창을 1280 → 375 → 1280 으로 바꾸면 숨김·보임이 따라가고, 숨을 때 100%로 돌아간다.
  - 대기 화면에는 알약이 없다. 다크 테마에서 % 글자가 보인다.
- 4 (미니맵)
  - 데스크톱·폰 경주 중: 미니맵 아래쪽을 누르면 `수동 카메라` 가 되고, 결승 구간이 보이고, 흰 네모가 아래로 간다. 누른 채 위로 끌면 출발 쪽까지 따라간다. 미니맵 밖으로 살짝 벗어나도 이어진다.
  - 순위표 줄 누르기는 그 동물 따라가기, 미니맵 밖 결승 스탠드 동물 탭은 반응이다. 미니맵 위에서는 미니맵이 이긴다. 미니맵을 끄는 중 두 번째 손가락은 카메라를 움직이지 않는다. 미니맵 더블클릭으로 자동으로 돌아가지 않는다.
  - 대기 화면: 미니맵 자리를 눌러도 수동이 되지 않고, 페이지 스크롤이 정상이다.
- 공통: 브라우저 2개 이상(방장 + 참가자 + 관전자)으로 실제 경주를 돌린다. 한 사람이 알약·미니맵을 써도 다른 클라의 `debug().manual.on`·`cam` 이 바뀌지 않는다. 콘솔 오류 0.

## 막힘 기준

- 세부 수치·배치(알약 `bottom`, 순위표 아래 여백, 장애물 페이드 시간)가 애매하면 기존 LAMDice 구조를 조사한 뒤 근거를 적고 합리적으로 고른다.
- 장애물의 차분한 처리(1번)가 마당 코드 구조상 무거우면, 차분한 모드에서는 장애물을 아예 내지 않는 쪽으로 물러선다. 튀는 동작을 남기는 쪽은 안 된다. 결정과 이유를 보고한다.
- 폰 판정의 `(hover: none) and (pointer: coarse)` 가 실제 기기(터치 노트북, iPad + 키보드 등)에서 어색하면, `view.narrow` 만으로 되돌리지 말고 기기별 결과를 적어 보고한다.
- 한 항목이 LAMDice 구조 때문에 원래 의도대로 안 되면 그 항목만 멈추고 이유를 보고한다. 나머지는 계속한다.
- iOS 14.4 이하 기기나 실제 폰 테스트가 불가능하면 grep·에뮬레이션으로 하고, 무엇을 못 봤는지 구체적으로 적는다.

## 범위 밖 — 발견했지만 이 goal 에서 하지 않는 것

- 다시 보기가 끝나 렌더 루프가 멈춘 화면(`stopReplay` → `renderer.stop()`, js/marble.js ~1076-1083)에서는 기존 드래그처럼 알약·미니맵 입력도 화면에 나오지 않는다. 1차 범위 밖 항목(스탠드 애니가 굳는 문제)과 같은 뿌리다. 이 goal 에선 그 상태에서 오류 없이 무시되는지만 본다.
- 폰에서 `mine` 분기를 타는데 선두가 프레임 구역에 있으면, 폰 줌 하한의 가로 따라가기(~683, `!frameMode` 조건)가 빠진다(코드로 추정). 3번의 알약 조건만 "실제로 탄 분기"로 바로잡고, 이 줄은 따로 확인한다.
- 공용 CSS 의 `inset`(예: `css/horse-shop.css` 상점 모달 등 여러 곳)도 iOS 14.4 이하에서 같은 증상을 낼 수 있다. 공용이라 여기서 바꾸지 않는다. iOS 14 전체 호환(`aspect-ratio` 등) 점검도 범위 밖이다.
- 결과 카드 동물 애니(1차 8번)는 reduced motion 에서 멈추는 기존 동작을 유지한다. 마당과 다르게 둘지는 따로 정한다.
