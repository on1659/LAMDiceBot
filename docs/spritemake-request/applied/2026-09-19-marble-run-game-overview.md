## 1. LAMDice가 뭔가

lamdice.com — 친구들끼리 **"오늘 음료수 살 사람 1명"을 뽑는** 실시간 파티 게임 사이트.
브라우저(PC·모바일)에서 방을 만들고 링크를 공유하면 최대 50명이 들어온다. 설치 없음.

이미 있는 게임 (전부 같은 목적 — 당첨자 1명 뽑기):

| 게임 | 방식 |
|---|---|
| 주사위 / 룰렛 / 사다리 | 고전. 숫자·색·줄을 고르고 결과를 본다 |
| 경마 | 탈것 15종(말·토끼·거북이·공룡·닌자·게…) 중 하나에 베팅, 경주 관전. 꼴등 말에 건 사람이 당첨 |
| 다리건너기 | 오징어게임 유리다리. 6색 캐릭터에 베팅, 떨어지는 걸 관전 |
| 회전 칼날 | 24명 배틀로얄 토너먼트 |
| 해적 룰렛 | 통에 칼 꽂기 |

공통 원칙: **결과는 서버가 정하고, 플레이어는 관전한다.** 조작 실력이 아니라 운으로 뽑는다. 그래서 화면은 "보는 재미"가 전부다.

용어:
- **당첨** = 벌칙자 (뽑히면 산다). 좋은 뜻이 아니다
- **방장** = 방 만든 사람. 설정하고 시작 버튼 누른다
- **준비** = 이번 판에 참가한다는 표시. 준비 안 한 사람은 관전만
- **라운드** = 한 판. 동점이면 동점자끼리 재경기

## 2. 마블런이 뭔가

> 쏙 웅크리고 데굴데굴 — 제일 늦게 굴러온 동물의 주인이 벌칙!

구슬 경주(마블런)인데 구슬이 **동물**이다. 고슴도치·아르마딜로·공벌레·거북이·판다 — 전부 실제로 몸을 말아 공이 되는 동물들. 플레이어는 이 중 하나를 고른다. 동물들이 봄 언덕 꼭대기 출발대에서 몸을 말고 굴러 내려가 골 바구니에 떨어지는데, **제일 늦게 도착한 동물의 주인이 당첨**이다.

경마와 같은 관전형이다. 굴러가는 동안 플레이어가 할 수 있는 건 없다. 고르고, 준비하고, 본다.

## 3. 한 판 흐름 (플레이어가 보는 순서)

```text
① 입장      방 링크로 들어옴. 채팅·참가자 목록 보임
② 동물 선택  5종 중 하나 고름. 같은 동물을 여러 명이 골라도 됨
③ 준비      준비 버튼. 준비한 사람 수 × n = 이번 판 동물 수 (n은 방장이 1~10 중 설정)
            예: 6명 준비, n=5 → 동물 30마리. 내 동물은 5마리 (같은 종, 같은 링 색, 숫자 ①~⑤)
④ 시작      방장이 시작. 카운트다운 3-2-1
⑤ 경주      30~60초 관전. 카메라가 무리를 따라 언덕 아래로 내려감
⑥ 결과      마지막 도착 동물에 스포트라이트 → 주인 이름 크게 → "당첨!" 팝업
            동점(마지막 도착이 여러 명 동시)이면 그 사람들끼리 재경기
⑦ 다음 판   방장이 n 바꾸거나 그대로 다시
```

투표 옵션: 경마처럼 "꼴등 말고 N등을 당첨으로" 투표할 수 있다. 기본은 꼴등.

## 4. 규칙 — 그림에 영향 주는 것만

- **동물 종족은 성능 차이가 없다.** 고슴도치를 고르든 판다를 고르든 굴러가는 물리는 완전히 같다 (같은 크기·무게·마찰). 그림만 다르다. → 공 형태는 5종 모두 같은 지름의 원 안에 있어야 한다
- **1인 n마리.** 내 동물이 여러 마리라 "내 것 중 하나"가 아니라 **전체 중 마지막 1마리**가 누구 것인지로 판정한다. 그래서 마지막 한 마리에 모든 시선이 몰린다
- **구분은 링 색 + 숫자.** 50명이 5종을 고르면 종족만으론 못 가린다. 코드가 공 바깥에 플레이어 색 링을 그리고 숫자 배지를 붙인다. 내 동물은 링이 밝고 이름표가 붙고, 남의 동물은 링만. → 스프라이트에 플레이어 색을 넣으면 안 된다
- **출발 위치는 서버가 섞는다.** 한 사람 동물이 전부 맨 밑에 깔리지 않게 줄 단위로 골고루 배치. 그림엔 영향 없지만 "출발대가 인원에 따라 넓어진다"는 뜻이다

## 5. 화면 — 뭐가 어디에 보이나

### 트랙

위에서 아래로 내려가는 **세로로 긴 언덕**. 좌우로 지그재그하며 내려간다. 트랙 한 판이 세 구간:

| 구간 | 세트피스 | 벌어지는 일 |
|---|---|---|
| 진입 | 출발대 → 울타리 깔때기 → 말뚝 밭 | 병목에서 첫 뒤섞임, 파칭코처럼 흩어짐 |
| 카오스 | 통나무 범퍼, 회전 풍차, 시소, 점프대, 진흙 웅덩이 | 튕기고 날아가고 빠지고. 순위가 뒤집힘 |
| 결승 | 울타리 병목 → 골 바구니 / 옆에 낡은 판자벽 | 마지막 한 마리 슬로모션 → 판자벽에 퍽 |

카메라는 판정 대상 무리(기본: 후미)를 따라간다. 전체화면 버튼이 있어 PC·모바일 모두 화면을 꽉 채울 수 있다.

### 그리기 순서 (뒤 → 앞)

```text
하늘·먼 산 (거의 안 움직임)
초원 잔디 타일 (카메라와 1:1 스크롤)
트랙 길 + 세트피스 (출발대·통나무·풍차·울타리·바구니 뒷면…)
동물 그림자 (코드)
동물 공들 (코드가 회전) + 플레이어 링·숫자 (코드)
골 바구니 앞면 (동물이 "안에 담긴" 느낌)
효과 (흙먼지·별·진흙 튐·웅크림 연기)
UI (순위 티커·내 동물 이름표·스포트라이트·당첨 팝업 — 전부 코드)
```

### 크기 감각

트랙 폭 800px에 공 지름 28px. 공이 50개면 넉넉하고 200개면 빽빽하다. 그래서 세트피스와 배경은 공보다 채도를 낮춰 공이 튀게 한다. 픽셀아트라 소스는 4배(공 112px)로 만들고 게임이 축소한다.

## 6. 감정 곡선 — 어느 장면이 왜 중요한가

```text
출발 "쏙"        전부 동시에 웅크리는 순간. 귀여움 폭발. 웃음 1
굴러가는 중       색깔 공 무리. 내 것 찾기. 튕길 때마다 "어어"
진흙 사고         펴져서 눈 @@ 멈춤 → 다시 웅크림. 웃음 2. 순위 뒤집히는 지점
마지막 한 마리    전원이 그 공만 봄. 긴장
판자벽 퍽 → 엎어짐   스포트라이트. 웃음 3 = 이 게임의 목적. 비참하면 안 되고 웃겨야 한다
골 바구니         나머지는 펴져서 손 흔들며 구경. 배경처럼 계속 움직임
```

에셋 우선순위가 이 순서다: **엎어짐 > 웅크림 > 공 > 펴짐 > 서 있음.**

## 7. 기술 — 그림 작업자가 알아야 할 것만

- 서버가 물리 시뮬레이션을 돌려 결과와 궤적을 정하고, 브라우저는 canvas에 재생만 한다. 그림이 물리 형상과 어긋나면 "허공에서 튕김"이 보이므로 세트피스는 규격 문서의 물리 형상 안에 딱 맞게 그린다
- 공은 코드가 회전시킨다. 회전 프레임 불필요. 공 그림은 어느 각도로 돌아도 이상하지 않아야 한다
- 풍차 날개·시소 판자도 코드가 회전시킨다. 회전 중심을 정중앙에, 대칭으로
- 링·숫자·이름·그림자·스포트라이트·텍스트는 코드가 그린다. 스프라이트에 넣지 않는다
- 픽셀아트, 정수 배율로만 확대·축소한다. 소스 4x
