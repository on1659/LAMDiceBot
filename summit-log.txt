  사람들이 자기 위치 고르는 거? 그런 거 없음. 이미 5개가 세팅되어 있고, 사람들은 몇 번에서 시작할지 고르는 거야."
- 이력을 뒤져 소유자가 기억하는 버전을 9f82a1c(2026-06-17)로 특정하고 그 메커니즘을 복원했다.
  그 뒤 53656e1(v2) → f7cafa1(pick-elimination) → dbd8f2a(v2 복원)로 세 번 갈아엎힌 구간이다.
- 9f82a1c 대비 변경 4가지: 레인 6→5, 번호 중복 선택 허용, 인원 상한 없음(LADDER_MAX_PLAYERS 삭제),
  「꽝」→「당첨」. 중복 허용 때문에 재경기가 새로 필요해졌다.

### [판정: 빈 레인은 당첨될 수 없다]
- 최종 보드로 laneToBottom 을 먼저 구한 뒤, **사람이 고른 레인 중에서** 서버 RNG 균등 추첨으로 winLane 을 뽑고
  winBottom = laneToBottom[winLane] 에 당첨 카드를 놓는다. 막대기는 한 개도 조작하지 않는다.
- 후보는 반드시 유니크 레인 집합이어야 한다 — Object.values 를 그대로 쓰면 3명 몰린 번호의 당첨 확률이 3배가 된다.
- 확률은 점유 레인 단위 균등(1/k). 막대기를 어떻게 그려도 분포는 불변(테스트로 고정).

### [재경기: 동시 당첨 → 그 사람들끼리 30초 자동 시작]
- 당첨자가 2명 이상이면 서버가 그들만 readyUsers 로 세팅하고 scheduledStartAt 을 걸어 예약 발화가 시작을 대신 누른다.
  경마(socket/horse.js:1358)와 같은 구조. 나머지는 준비가 풀려 관전이 된다.
- 재경기가 걸린 판에서는 주문받기 자동 시작을 열지 않는다(아직 최종 결과가 아니므로).
- scheduled-start 의 SUPPORTED_GAME_TYPES 에 ladder 를 등록해야 발화한다 — 등록 없이는 require(undefined) 로
  조용히 죽고 예약만 사라진다.

### [구조: 엔진을 모듈 레벨로 분리]
- 예약 스위퍼가 넘기는 ctx 는 { rooms, updateRoomsList } 뿐이라(socket/index.js) 소켓 클로저의 헬퍼에 기댈 수 없다.
  게임 로직을 createLadderEngine(io, ctx) 로 빼고 module.exports.canStart / .start 를 노출했다.
- 주의: 엔진 멤버를 일부만 구조분해하면 빠뜨린 이름이 핸들러 실행 시점에 ReferenceError 로 터지고,

## 상세 변경 내역

### [메커니즘 교체: pick-elimination → v2 실제 사다리타기]
- 배경: 실플레이 판정에서 "남의 그림이 안 보인다 / 하강이 동기가 안 맞는다 / 게임이 진행이 안 된다"가 보고됨.
  조사 결과 "남의 그림이 안 보임"은 pick-elimination의 숨은 막대기 설계 자체였고(의도된 동작),
  나머지는 실제 버그였다. 소유자 결정: v2를 복원한다.
- 복원 범위: 모든 참가자의 막대기가 실시간으로 서로 보이고, 위·아래 칸 라벨을 함께 편집하며,
  서버가 바닥 라벨을 셔플(perm)해 결과를 정한다. 라우트 /ladder와 등록 지점은 전부 그대로.

### [버그 수정: 내가 그린 선이 제멋대로 변형되던 문제]
- 원인: buildLadder의 union이 points 배열 참조를 ld.userRungs / ld.baseRungs와 공유했고,
  resolveContacts가 그 배열을 제자리에서 변형해 원본까지 오염시켰다.
- 기존 커밋 fef0280은 user 분기 한쪽만, 그것도 pick-elimination에서만 고쳤다 — 절반짜리 수정.
- 조치: user 분기와 base 분기 양쪽 모두에서 points를 깊은 복사. added↔rungs 참조 공유 계약(내부 생성 객체)은
  그대로 두고, 원본과의 aliasing만 끊었다. buildLadder+reveal 후 원본이 바이트 단위로 불변인지 회귀 assert 추가.

### [동시 하강을 기본값으로 — 전 지점 일괄 전환]

  클라 초기 미러 2곳·폴백 2곳, 토글 UI 초기 상태, 테스트 assert까지 한 커밋에서 함께 뒤집었다.

- 프리셋은 시각 칸을 채울 뿐(emit 안 함). [예약]이 커밋.
- 방 만료 이후가 되는 프리셋은 숨김(data-schedule-minutes + roomExpiresAtMs).
- 카운트다운과 발화 안내가 같은 DOM 요소를 돌려쓴다 — 나누면 발화 순간
  배지 소멸 + 토스트 + 3-2-1 오버레이가 3중으로 겹친다.
- 주사위 버그 수정: 안내 5초 후 카운트다운으로 복귀하지 않아 남은 시간이 영영 안 보이던 문제

- **균형 생성:** `generateBaseRungs`(0~RAND extra)와 `buildLadder` 스크램블(erase K / add M / density fill)이 N−1 컬럼 × 수직 밴드(top/mid/bottom)에 균등 분포 — 한 영역 쏠림 방지. `rungTooClose` 간격 규칙 + 서버 RNG 유지. 당첨 분포는 placement와 독립(불변).
